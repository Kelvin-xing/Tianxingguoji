## 1. v55 核对及已移出的阻塞

- **D5 的“是否允许首次全量导入”已确认**：以 EDB 名单一次性全量抓取/导入，作为初始目录；不能继续要求负责人批准其允许性，也不能扩大为任意人工批量更新。
- **D6 的“是否允许无人周期抓取”已确认**：逐校设置频率，最快每天一次；不是全局统一频率，也不是自动启用后续资料变化。
- v49 仅豁免首次一次性 EDB 导入自动带入的网址；后续人工来源添加/修改仍须 Founder 审批。D1 不能重新设置初始学校或 EDB 网址的逐条审批。
- 学校免额外审批进入可用状态、界面不显示 provisional 未验证标记均已确认，原始记录不可变永久保留。D7 的这两部分不阻塞。
- **D7 仍有剩余语义空白**：v55 未明确“可用”与 Cases 候选学校可选资格是否等同；[BR-033](../../../txgj-doc/business-requirements/30-cases.zh-CN.md) 规定的是名单审批、Guardian 确认及后续处理顺序，没有补出这一对应关系。本清单只判定需澄清，既不认定“可用即无条件可选”，也不新增未验证审批门槛。

D5/D6 不再作为整项待批准门禁；原复合条目中 v55 未覆盖的细节，按内容归回已有问题或在 §5 单列“新发现”，不能因允许性获批便自行填写答案。原设计文档保持原文，本清单以现行 BR 为准。

## 2. 分类口径

| 阶段 | 沿用的交付含义 |
| --- | --- |
| A 契约与样本 | 学校/招生身份、新版本格式、业务 API 及合成样本 |
| B 接入预检 | 候选输入、身份核对、字段映射、差异与阻塞原因；不写正式目录 |
| C 后台及数据库 | 任务、候选、生效、人工审批、履历、恢复及事务约束 |
| D 页面与 Cases | 四块详情、统一查询、选校及固定版本引用 |
| E 真实小样本联调 | 经核对来源与真实候选的完整流程；不等于全量运营验收 |

“最早阻塞”指**对应交付部分**最先需要答案的位置，不等于整个阶段都不能开始。例如 A 中一个操作的授权契约未定，不妨碍其余已明确的数据契约；但不能把该操作也宣布冻结。表中“可挂起”只表示暂不实现或验收该未决分支，绝不表示先按某个默认答案做。

“真实数据有帮助”只评价决策材料，不授权抓取或启用。可查看已有来源样本后再决策，不必等 E 已经开始；E 遇到未定分支仍不能拿真实资料试错。“不阻塞”限定已确认的 A–E 核心闭环，不能理解为相关扩展能力已经完成。

## 6. 必须先定什么，哪些可以挂起

**面向 A 的共用学校/招生身份契约实现，最小前置收敛为两项：D4 的学校对象粒度、N2 的招生记录身份判定。**这里只要求明确共用对象含义，不要求在第一行代码前把所有多校址个案、异常候选和治理流程处理完；也没有替负责人选择粒度或对应规则。若只统计用户点名的原 17 项，最小前置就是 **D4 的共用粒度部分**。

“写第一行代码”若严格指任何辅助代码，没有待决项能阻止已确认且与它无关的工作；本结论针对会固化共用业务身份的实际开工，不把写文件解析等局部工作冒充 A 已完成。未经确认的技术设计也不会因本分类自动获批。

其余可挂起，但有明确截止点：

- **D1、D2、U1–U3、N7 的授权部分**：不用挡共用身份/格式工作；但各自操作契约不能先填默认答案，也不能在 A 整体验收时当作已冻结。U3 随 U1/U2 的选择决定是否需要展开，不单独加一道全局门槛。
- **D3、N1、N3、N4 及 N7 的运营部分**：到 C 对应写入/状态转换前收口；**D7 剩余**到 D 的 Cases 可选资格实现前收口。它们没有必要阻止 A/B 的独立已确认部分。
- **T1–T9**：可整体挂起退场功能；到 C/D 的对应退场行为前再定。不能在有退场样本时宣称 E 全流程已完成，更不能把小样本可运行说成已能处理全量运营中的停办/录错学校。
- **N5、N6**：不阻塞已确认核心闭环；选择增加相应操作时再定。未实现与默认允许/默认拒绝某业务决定不是同一件事。

E 不是“把所有决策都推迟到看到真实数据再说”的阶段。适合看数据的项可以先用已有样本辅助决定；涉及身份和实际写入的答案，仍须在它第一次被固化或执行之前明确。允许其他分支推进，不表示未决分支获准试做。
