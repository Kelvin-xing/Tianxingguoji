# 第一期 K12 试用版权限矩阵与开发计划

日期：2026-09-19。状态：试用方案已获项目负责人授权实施，开发进行中，客户未逐项验收。当前证据及未完成项见 `ACCESS-TRIAL-01_PROGRESS.md`。

## 1. 范围与依据

仅服务天星教育一个组织，第一期仅 K12。国际学校、本地学校仍可作为 K12 内业务分类，不因第一期只有 K12 而取消分类权限。

项目负责人授权先做试用版本，通过客户实际使用收集反馈。以下“暂定”是试用假设，不表示客户已确认。不得用试用方案声称生产权限已经变更。

现行需求对照：BR-001/003 产品范围；BR-010/011/012/013/014 身份权限；BR-030/032/033/034 案件与审批；BR-035–037 任务；BR-050 文件；BR-070/071 审计。实施前先将试用授权及与旧规则的差异同步到所属需求模块和 CHANGELOG，保留旧模型追溯，不能将旧模型与新模型权限直接取并集。

## 2. 已明确的方向

| 等级 | 项目负责人描述的范围 |
| --- | --- |
| 创始人 | 全部权限 |
| L1 | 业务权限等于创始人，但不能设置其他员工等级 |
| L2 | 负责获授权的业务分类，例如国际学校或本地学校 |
| L3 | 按 L2 及以上的指派工作，可同时接受不同分类的案件或任务 |

## 3. 可供客户试用的矩阵

“范围内”始终同时受账号状态、业务分类、案件/任务关系和资源状态约束。

| 操作 | 创始人 | L1 | L2 | L3 | 试用假设 |
| --- | --- | --- | --- | --- | --- |
| 查看学生、家长、案件 | 全部 | 全部 | 获授权分类关联的记录 | 当前任务必要资料 | L3 不自动获得完整案件档案 |
| 建案、维护评估及选校 | 全部 | 全部 | 获授权分类内 | 无整案修改权限 | L2 可处理分类内全部案件 |
| 指派案件或任务给 L3 | 全部 | 全部 | 获授权分类内 | 不可转派 | 指派不能超出指派者范围 |
| 执行、更新任务 | 全部 | 全部 | 获授权分类内 | 当前被指派任务 | 完成任务不等于审批案件 |
| 审批候选学校名单、结案 | 全部 | 全部 | 暂不允许 | 暂不允许 | L2 审批能力待试用反馈 |
| 查看及上传文件 | 全部业务范围 | 全部业务范围 | 获授权分类内 | 任务明确关联且允许操作的文件 | 不开放全案文件列表；下载仍受安全状态校验 |

| 编辑本人昵称 | 可以 | 可以 | 可以 | 可以 | 不借此改变等级、邮箱或权限 |
| 查看审计 | 全部 | 业务操作记录 | 分类内业务记录 | 本人任务操作记录 | 完整安全/账号审计只给创始人 |
| 配置凭据及系统安全设置 | 可以 | 暂不允许 | 不可 | 不可 | L1 的全部业务权限不等于基础设施管理权限 |

## 4. 暂定细节登记

| 编号 | 暂定规则 | 客户反馈时观察 |
| --- | --- | --- |
| T01 | L3 采用任务级授权；案件只是任务上下文 | 是否缺少必要上下文，是否应给整案责任 |
| T02 | L2 可获多个分类；L201/L202 作为显示编码，底层按等级＋分类授权 | 是否确实需要独立编码或单分类限制 |
| T03 | 创始人和 L1 仍遵守必填、扫描、审计、不可重复写入等业务约束 | “无限制”是否另指特殊业务流程豁免；本版不提供绕过审计功能 |
| T04 | 试用样例每个案件只属一个分类；不按同一学生自动共享其他案件 | 混合选校案件如何划分；第一版不自动扩大为跨分类可见 |
| T05 | L3 指派撤销或转交后立即失去操作权限；任务完成后只读至指派撤销 | 历史查阅是否满足工作需要 |
| T06 | 导出、批量下载不新增授权 | 是否存在实际交付需求 |
| T07 | 当前 FULL_TIME/PART_TIME 是员工资料，不直接映射 L1/L2/L3 | 不把兼职自动等同 L3，不把 Admin 自动等同 L1 |

## 5. 开发顺序与验收

| 票据 | 交付 | 验收标准 | 依赖 |
| --- | --- | --- | --- |
| A 试用规则与授权契约 | 同步需求中的试用边界；建立等级、分类、资源动作矩阵及默认拒绝规则 | 覆盖四等级、两分类、指派及撤销的允许/拒绝决策；不改变旧账号权限 | 本计划 |
| B 数据与合成账号 | 追加迁移、分类授权、案件分类与指派；建立四等级试用样例 | PostgreSQL 17 空库重放；无第二组织；旧数据不丢失；未知分类拒绝访问 | A |
| C 服务端接通 | 列表、搜索、详情、写入、审批、文件、任务统一授权；事务内重查 | 隐藏按钮后直接调用 API 仍被拒绝；撤权后的旧 Session 无法继续写入；审计正确 | B |
| D 页面接通 | 员工等级及范围管理、指派入口、不同等级工作台及拒绝提示 | UI 与 API 一致；L3 无整案入口；L1 无员工等级设置入口；移动端可操作 | C |
| E 本地试用验收 | 真实数据库＋浏览器完整场景及缺陷修复 | 创始人设置、L1 业务审批、L2 分类管理、L3 任务操作、撤销生效均通过 | D |
| F 客户测试环境 | 确定隔离部署目标、账号交付方式、数据和恢复方案后部署 | 客户可登录；反馈可定位到角色、页面、操作、预期与实际结果 | E；独立部署授权 |

本计划不指定新云服务，不执行生产部署。已有方向为阿里云香港，应用和 Docker PostgreSQL 同机，OSS 保存文件与备份；服务器产品、规格及测试部署目标仍待具体落实。

技术重点：不能只改角色名称。当前 capability 合并、兼容角色转换、案件负责人条件、数据库角色校验和邀请函数均需逐条适配，尤其旧 Founder 无自动顾问权限、旧 Admin 可管理成员的行为与新方案不同。

## 6. 样例与客户反馈

合成账号：创始人、L1、国际学校 L2、本地学校 L2、L3。L3 同时收到两个分类的任务；另设未指派案件验证不可见。全部样例仍属于天星教育一个组织。

演示顺序：创始人分配等级和分类 → L2 处理本分类案件并指派 → L3 完成任务 → L1 审批业务 → 撤销指派并确认权限收回。不要求客户理解数据库或权限术语。

## 7. 发布与回退边界

本地先使用合成数据。旧用户不自动授予新高等级，映射清单由项目负责人审阅；新增迁移不重写历史。上线前保留数据库备份和应用版本；若新权限已产生业务写入，不直接回退到旧角色模型，需要验证数据兼容性。提交、推送、部署、真实员工权限变更另行执行授权。

计划编制时的验证（历史记录）：已对照当时权限源码与需求，完成文档矩阵和票据依赖审阅。未运行测试，未改业务源码，未迁移数据库，未部署；不代表试用版本已经可用。
